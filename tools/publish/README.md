# tools/publish

Copies the public part of this repository into the public one, one commit per internal commit.

| File | What it is |
| --- | --- |
| `allowlist` | The paths that are public. Nothing else is copied. |
| `export` | `--list`, `--tree`, `--dir` and `--filter`: the allowlisted files of a commit, and the tree made from them. |
| `publish` | Builds the new public commits, scans them and pushes them to a target. A dry run unless `--apply` is given. |
| `scan` | The scan: internal words, hosts, ids, names, mail domains and stray keys, in a tree (paths and file text) and in a commit (author, committer, message and trailers). |
| `ci/run` | What `.github/workflows/publish.yml` runs, once per target. Takes the target and its push credential from the environment. |
| `test`, `t/` | The tests, in temporary repositories. Run `tools/publish/test`. |

Rules, in short:

- The export is exactly the files the allowlist names, with their modes. The internal repository's operating scripts (`docs/ops/`) are left out by the allowlist. A few paths (`evals/`, `docs/plans/`, the scan's internal folder) are never public: they are left out even when a folder above them is listed, and an allowlist that names one is refused.
- The first publish is one commit with no history, and it must hold `LICENSE`. After that, each internal commit that changes something public becomes one public commit: the bot identity as author and committer, the internal commit's author date, the subject line only (the ` (#<number>)` the merge adds is cut), no body and no trailer.
- A subject that still holds an internal pull request number after that cut, in the merge's own forms, is refused, and the run stops there: a number after a `#` alone in brackets anywhere else in it (`(#12)`, as in a revert's subject `Revert "X (#12)" (#13)`), or a merge subject (`Merge pull request #12`, `Merge pull-request #3`, `Merge PR #3`, in any case). So is U+266F (the music sharp sign) used as a `#` before a number (after a letter, as in a chord's name, it stays). The way past, which the stop names: a line `<the commit's full id> <a public subject>` in `tools/publish/internal/subjects` (never public), merged to main. The next run gives that commit the subject from the line, made and scanned as any other; the commit that adds the line changes nothing public and is skipped.
- Then each `#` before a number at the start of a word (not after a letter, a digit or `_`) is taken out, as it would link to a pull request in the public repository: `follow-up to #149` is published as `follow-up to 149`, `Fix the thing from #77` as `Fix the thing from 77`, `Fix [#12] now` as `Fix [12] now`, `Fix both (#12, #13)` as `Fix both (12, 13)`; `C#9` stays as it is. Both steps read the subject as the scan does: a full-width `#` or digits, and a `#` split from its number by an invisible character, count. `tools/publish/scan subject` makes the public subject; the scan's check of the public commit is the backstop.
- The target's head must be an export of a commit in this history. Anything else is refused, and nothing is ever forced.
- The workflow has two targets, each its own step with its own credential: the staging copy (`GP_PUBLISH_TOKEN`, `GP_PUBLISH_REPO`) and the public repository (`GP_PUBLISH_TOKEN_PUBLIC`, a secret of the `publish` environment, and `GP_PUBLISH_REPO_PUBLIC`). A target whose credential or name is not set is skipped with a notice. They publish the same internal commits from the same run, each from its own head, so their commit ids differ (the public one starts with its own first commit) and their trees are the same. A target that fails is left as it was and does not stop the other; the next run brings it up to date. A target must be created empty: one that holds anything else (a README or licence added by the host) is not an export and is refused.
- Nothing is pushed unless the scan passes on the files each commit adds or changes, and on each public commit it made. Of a commit's fields, the scan reads what goes public: the public commit itself, so the cut subject and the bot as author and committer. When git made the subject from several lines of the internal message (it joins them with spaces), the scan also reads those lines each as its own line, so a word-list rule tied to a line (`^`, `$`, a line break) still sees them. Whatever the scan program, `publish` refuses a public commit whose message, read back from the commit it made, is more than one line. The internal commit's body, trailers, author and committer are never published, and are not scanned. With no scan, nothing is published. One hit stops the whole run; the output names a rule and a place, never the text.
- The scan reads every text twice, as it is and normalised: the Unicode default-ignorable characters (zero-width spaces and joiners, the soft hyphen, bidi marks and the rest of that class) taken out, and NFKC (full-width letters and digits become plain ones), and the dashes made `-`: every Unicode dash punctuation character (category Pd: the hyphen, the en and em dash, the wave dash, the two- and three-em dash, the Armenian and Hebrew hyphens and the rest), and U+2212 (minus), U+02D7 (modifier letter minus), U+2043 (hyphen bullet) and U+2796 (heavy minus). So a word split by an invisible character, written full-width, or with a look-alike dash for its `-`, is still found, in a file, a path or a commit. A text the scan cannot normalise is a hit. A commit that is not UTF-8, or has an `encoding` header other than UTF-8, is refused, never decoded. A public commit is refused when its message holds an internal pull request number in one of the merge's forms above, or a `#` (or U+266F) before a number at the start of a word (publish takes those out or refuses them, so none should be left), in either reading.
- The scan's full word list is `tools/publish/internal/words.txt`, which is never exported. The public part of the list is built into `scan` (and `install/test/clean-tree.test.sh`), in pieces.
- `clean-tree` scans only the files the allowlist names, so folders that stay internal can live in the internal repository.

The bot identity is `GP_PUBLISH_NAME` and `GP_PUBLISH_EMAIL` (a `users.noreply.github.com` address).
